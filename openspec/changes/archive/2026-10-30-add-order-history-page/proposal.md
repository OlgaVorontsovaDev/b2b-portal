# Proposal

## Why

В B2B-портале нет страницы, где клиент видит свои прошлые заказы. Бэкенд пока не готов, поэтому страницу нужно собрать на мок-API, чтобы согласовать UI и поведение (пагинация, фильтрация) до интеграции с реальным сервисом.

## What Changes

- Новая страница «История заказов» с таблицей заказов (номер, дата, статус, сумма).
- Постраничный вывод по 10 заказов с навигацией между страницами.
- Фильтр по статусу заказа; при смене фильтра пагинация сбрасывается на первую страницу.
- Состояния загрузки, ошибки и пустого результата.
- Слой данных на мок-API с асинхронным интерфейсом, повторяющим будущий серверный контракт (параметры `page`, `pageSize`, `status`). Переход на реальный API не должен менять UI.
- Замена демо-содержимого `src/App.tsx` (шаблон Vite) на каркас приложения, в котором отображается страница.

Допущения (можно изменить на этапе ревью):
- Статусы: `new`, `processing`, `shipped`, `delivered`, `cancelled`; фильтр одиночный, плюс значение «Все».
- Сортировка фиксированная: сначала новые заказы.
- Роутер не добавляется: страница единственная, рендерится из `App`.
- Состояние фильтра и страницы хранится в состоянии компонента, не в URL.
- Мок содержит около 45 заказов, чтобы пагинация была заметна; имитируется задержка сети.
- Интерфейс на русском языке.

Вне рамок: детальная страница заказа, поиск, сортировка по колонкам, экспорт, авторизация, реальный бэкенд.

## Capabilities

### New Capabilities
- `order-history`: просмотр списка заказов клиента с пагинацией по 10 элементов и фильтрацией по статусу, включая состояния загрузки, ошибки и пустого списка.

### Modified Capabilities

(нет, существующих спецификаций в проекте нет)

## Impact

- Код: `b2b-portal/src` (`App.tsx`, новые модули страницы, типов и мок-API, стили).
- Зависимости: не планируются новые, используются React 19 и Vite из текущего `package.json`.
- Тестовой инфраструктуры в проекте нет; проверка опирается на `npm run build` и `npm run lint`, а решение о добавлении тестов вынесено в design.md.
- Внешние системы: нет, мок-API локальный.
