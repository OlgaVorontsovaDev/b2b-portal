# Design

## Context

Проект содержит шаблон Vite + React 19 + TypeScript (`src/App.tsx` с демо-содержимым). Роутера, UI-библиотек, менеджера состояния и тестового раннера нет. Включены `erasableSyntaxOnly` и `verbatimModuleSyntax`: нельзя использовать `enum` и `namespace`, типы импортируются через `import type`. Линтер: oxlint. Мотивация и допущения: см. proposal.md; требования: см. specs/order-history/spec.md.

## Goals / Non-Goals

**Goals:**
- Граница между UI и данными, которая при подключении реального API меняется в одном модуле.
- Корректная обработка гонок запросов при быстрой смене фильтра и страницы.

**Non-Goals:**
- Кэширование ответов, серверное состояние (React Query и подобные).
- Синхронизация страницы и фильтра с URL.
- Адаптивная вёрстка сложнее базовой (горизонтальная прокрутка таблицы на узких экранах достаточна).

## Decisions

**Структура модулей** (папка по функциональности):
```
src/features/orders/
  types.ts            // Order, OrderStatus, OrdersQuery, OrdersPage
  ordersApi.ts        // fetchOrders(query, signal): Promise<OrdersPage>
  mockOrders.ts       // статические данные
  useOrders.ts        // хук: состояние запроса + page/status
  OrderHistoryPage.tsx
  OrdersTable.tsx
  StatusFilter.tsx
  Pagination.tsx
  OrderHistoryPage.css
```

**Контракт API.** `fetchOrders({ page, pageSize, status }, signal)` возвращает `{ items, total }`; `status` необязателен (нет значения = «Все»). Фильтрация и срез выполняются внутри `ordersApi.ts`, как это сделал бы сервер. Компоненты не знают, что данные мок. Мок эмулирует задержку 300–600 мс и поддерживает `AbortSignal`.
- Альтернатива: фильтровать и резать на клиенте в компоненте. Отвергнуто: при переходе на реальный API пришлось бы переписывать UI.

**Типы статусов.** `OrderStatus` объявляется как union строковых литералов и константа-массив `as const`, не `enum` (запрещён `erasableSyntaxOnly`). Подписи на русском хранятся в одной таблице соответствия.

**Состояние.** `useOrders` держит `page` и `status` в `useState`, результат запроса в `useState` с вариантами `loading | error | success`. Смена статуса одновременно ставит `page = 1` в одном обработчике (требование «сброс страницы»), без отдельного эффекта.
- Альтернатива: `useReducer`. Состояний мало, лишняя церемония.

**Гонки запросов.** Запрос выполняется в `useEffect` с `AbortController`; cleanup эффекта вызывает `abort()`, а результат отменённого запроса игнорируется. Это обеспечивает сценарий «быстрая смена фильтра» из спецификации. Повтор после ошибки реализуется счётчиком `retryKey` в зависимостях эффекта.

**Сумма и дата.** Форматируются через `Intl.NumberFormat('ru-RU', { style: 'currency', currency: 'RUB' })` и `Intl.DateTimeFormat('ru-RU')`. Сумма в мок-данных хранится целым числом (рубли), даты в ISO-строках.

**Пагинация.** Кнопки «Назад» / «Вперёд» и индикатор «Страница N из M». Номера страниц списком не нужны для 5 страниц и усложняют проверку. Число страниц: `Math.max(1, Math.ceil(total / 10))`. При `total = 0` навигация скрывается.

**Доступность.** Таблица на семантических `<table>`, фильтр на `<select>` с `<label>`, индикатор загрузки и ошибка в области `role="status"` / `role="alert"`.

**Проверка.** Тестового раннера в проекте нет. Базово: `npm run build` (проверка типов) и `npm run lint`. Логику `fetchOrders` (фильтр, срез, total) проверить вручную в браузере по сценариям спецификации. Добавление Vitest не входит в этот change.
- Альтернатива: добавить Vitest + Testing Library. Полезно, но это новая зависимость и инфраструктура; выносится на отдельное решение.

## Risks / Trade-offs

- [Мок-контракт разойдётся с реальным API] → Контракт изолирован в `types.ts` и `ordersApi.ts`; при появлении бэкенда сверить имена параметров и форму ответа.
- [Состояние не в URL: обновление страницы сбрасывает фильтр] → Принято как допущение; при необходимости вынести в отдельный change.
- [Нет автотестов] → Риск регрессий при развитии; смягчается небольшим объёмом кода и ручной проверкой по сценариям спецификации.
- [Индикатор загрузки при каждой смене страницы вызывает мерцание] → Принято: индикатор показывается вместо таблицы, как в спецификации. Мок-задержка короткая, поэтому мерцание допустимо.
