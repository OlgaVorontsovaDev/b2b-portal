# Spec Delta

## Purpose

Позволяет клиенту B2B-портала просматривать список своих прошлых заказов постранично и отбирать их по статусу.

## ADDED Requirements

### Requirement: Отображение списка заказов
Система SHALL показывать на странице истории заказов таблицу заказов с номером, датой, статусом и суммой каждого заказа. Заказы MUST быть упорядочены от новых к старым по дате.

#### Scenario: Открытие страницы
- **WHEN** пользователь открывает страницу истории заказов
- **THEN** система показывает первую страницу заказов, отсортированных от новых к старым

#### Scenario: Данные заказа в строке
- **WHEN** заказ отображается в списке
- **THEN** строка содержит номер заказа, дату, статус и сумму

### Requirement: Постраничный вывод по 10 заказов
Система SHALL показывать не более 10 заказов на странице и предоставлять навигацию между страницами.

#### Scenario: Полная страница
- **WHEN** подходящих заказов больше 10
- **THEN** на странице отображаются ровно 10 заказов и доступна навигация на следующую страницу

#### Scenario: Последняя неполная страница
- **WHEN** пользователь переходит на последнюю страницу, а подходящих заказов не кратно 10
- **THEN** отображаются оставшиеся заказы, а переход вперёд недоступен

#### Scenario: Первая страница
- **WHEN** пользователь находится на первой странице
- **THEN** переход назад недоступен

#### Scenario: Индикация положения
- **WHEN** отображается любая страница
- **THEN** пользователь видит номер текущей страницы и общее число страниц

### Requirement: Фильтрация по статусу
Система SHALL позволять выбрать один статус заказа или значение «Все» и показывать только заказы с выбранным статусом. По умолчанию MUST быть выбрано «Все».

#### Scenario: Выбор статуса
- **WHEN** пользователь выбирает статус «Отменён»
- **THEN** в списке остаются только заказы со статусом «Отменён»

#### Scenario: Сброс фильтра
- **WHEN** пользователь выбирает значение «Все»
- **THEN** в списке снова отображаются заказы всех статусов

#### Scenario: Пагинация учитывает фильтр
- **WHEN** фильтр применён
- **THEN** число страниц вычисляется по количеству заказов с выбранным статусом

### Requirement: Сброс страницы при смене фильтра
Система SHALL при изменении фильтра возвращать пользователя на первую страницу результатов.

#### Scenario: Смена фильтра на дальней странице
- **WHEN** пользователь находится на третьей странице и меняет статус в фильтре
- **THEN** отображается первая страница отфильтрованного списка

### Requirement: Состояние загрузки
Система SHALL показывать индикатор загрузки, пока данные запрашиваются, и MUST блокировать повторные переходы между страницами на время запроса или отображать актуальный результат последнего запроса.

#### Scenario: Первичная загрузка
- **WHEN** страница открыта и данные ещё не получены
- **THEN** вместо таблицы отображается индикатор загрузки

#### Scenario: Быстрая смена фильтра
- **WHEN** пользователь меняет фильтр до завершения предыдущего запроса
- **THEN** итоговый список соответствует последнему выбранному фильтру

### Requirement: Состояние ошибки
Система SHALL при неудачном запросе показывать сообщение об ошибке и действие «Повторить», выполняющее тот же запрос заново.

#### Scenario: Сбой запроса
- **WHEN** запрос списка заказов завершается ошибкой
- **THEN** пользователь видит сообщение об ошибке и кнопку «Повторить»

#### Scenario: Повтор после ошибки
- **WHEN** пользователь нажимает «Повторить»
- **THEN** выполняется запрос с теми же страницей и фильтром, и при успехе отображается список

### Requirement: Пустой результат
Система SHALL показывать сообщение об отсутствии заказов, если по текущему фильтру ничего не найдено.

#### Scenario: Нет заказов с выбранным статусом
- **WHEN** по выбранному статусу нет ни одного заказа
- **THEN** отображается сообщение «Заказы не найдены», а навигация по страницам скрыта
